一、环境与构建
-------------------------------------------------------------------------------
* 语言/工具链：C++ / Win32 API，MSVC v142（VS2019），Release / Win32
* 编译脚本：
    E:\EE317-GYY\BrainBay\tools\build_brainbay.bat
      - 增量编译 brainBay.sln（Release / Win32 / v142）
      - 结束后把 src\Release\BrainBay.exe 复制到 ..\bin\BrainBay.exe
      - 输出 BUILD_EXITCODE=0 / COPY_EXITCODE=0 表示成功
* **【大坑 1】头文件里的类成员一改动，必须完整重编译**
    MSBuild 增量编译时 globals.cpp 里的 new 可能仍用旧的 sizeof，
    运行时会堆损坏 0xC0000374。改 *.h 后必须：
      MSBuild.exe brainBay.sln /t:Rebuild /p:Configuration=Release
                  /p:Platform=Win32 /p:PlatformToolset=v142
* **【大坑 2】bin\BrainBay.exe 会被 Visual Studio 的 Debug 构建覆盖**
    brainBay.vcxproj 的生成后事件无条件把输出复制到 ..\bin。
    Release 大小 ≈ 4,133,888 字节；Debug 大小 ≈ 7,750,000 字节。
    运行前先确认 bin\BrainBay.exe 是 4.1 MB，否则跑的是 Debug 版。
    （待办：把 post-build 改成只在 Release 配置下复制）
* **【大坑 3】exe 被占用时复制失败**
    BrainBay 正在运行时 copy 会失败（COPY_EXITCODE=1）。
    变通办法：先给运行中的 exe 改名，再复制：
      Move-Item bin\BrainBay.exe bin\BrainBay.exe.prev -Force
      Copy-Item src\Release\BrainBay.exe bin\BrainBay.exe -Force
    （Windows 允许重命名正在运行的 exe）

三、两个设计文件的关键差异
-------------------------------------------------------------------------------
目录：bin\CONFIGURATIONS\EEG\
  physioamp_flash_neuropuzzles.con   （老的“阈值直驱”版本）
  physioamp_flash_puzzle.con         （照宝尔 bxd 重做的版本，10 个对象）

                          neuropuzzles            puzzle
  Flash channels          3 (In1/In2/In3)         2 (In1/In2)
  Flash drive             0（原值透传）            1（内部生成）
  gateport                —                       0
  scorems / clockms       —                       1000 / 1000
  阈值去向                直接进 Flash 三个输入     先过两个 AND，只用来开关计分闸门
  两者都能正常运行；差别只在“游戏怎么被推进”。

physioamp_flash_puzzle.con 结构（10 个对象）
   0  EEG        PhysioAmp devicetype=15，3000 Hz
   1  ARTIFACT
   2  BAND-POWER 前 7 个频带（bp_first=0, bp_cells=7, bp_columns=1,
                 bp_hl=50, bp_units=3 → µV RMS）
   3  THRESHOLD  ATTENTION  SMR 12-15 Hz ≥ 5 uV   interval_len=3000
   4  THRESHOLD  DISTRACT   theta 4-8 Hz ≤ 20 uV  interval_len=3000
   5  THRESHOLD  TENSION    beta 22-30 Hz ≤ 20 uV interval_len=6000
   6  AND        3 + 4
   7  AND        5 + 6
   8  FLASH      swf = C:\Program Files (x86)\BioExplorer\Flash\simpleAdapterLoader.swf
                 channels=2, drive=1, gateport=0, scorevar=In1, clockvar=In2
   9  BAND-POWER 7 个比值（bp_first=7, bp_cells=7, bp_hl=0, bp_units=3）
* 信号流（照抄宝尔 .bxd 的思路）：
    三个阈值 → AND → AND → Flash.gateport
    闸门打开时 In1(计分) 每秒 +1；In2(心跳) 一直 +1；
    NeuroPuzzles 的 In1In2InputModel 只在 In1 增长时前进 → 画面推进

五、已确认的问题与根因（历史，避免重犯）
-------------------------------------------------------------------------------
1) 游戏画面静止不动
   → 变量名写成 in1/in2；必须 In1/In2（大小写敏感）
2) 阈值从未触发，闸门一直关
   → 脑电输入满量程饱和：PhysioAmp raw: min≈40 max≈65520 spread≈65490
     典型是电极悬空 / 参考或接地没接好 / 导联松脱。
     theta 27~1660 µV、beta 1~170 µV 远超阈值 20 µV → DISTRACT 几乎永不满足
3) “必要的系统组件未能正常运行，请修复 Adobe Flash Player” 错误页
   → 与设计文件无关（两个设计在 Flash 层日志完全一致）。
     已定位为界面改动的副作用，回退后消失：
       a. 给 Flash 窗口加了 WM_PAINT 并整块填充客户区
          → 覆盖了 ActiveX 子窗口（父窗口没有 WS_CLIPCHILDREN）
       b. 去掉 WS_CAPTION + 把 ActiveX 内缩 3px 做自绘边框
       c. bin 被 7.75 MB 的 Debug 构建覆盖
     教训：Flash 面板上不要做“覆盖客户区”的绘制；要留边框只能改非客户区，
           或把控件内缩并只画边框带，且必须加 WS_CLIPCHILDREN
4) 设置对话框关不掉
   → 各对话框过程开头有 if (st->type != OB_X) return FALSE;，
     actobject 变化后所有消息（含 WM_CLOSE）都被丢弃。
     已在 darkmode.cpp 的 WM_CLOSE 兜底 + close_toolbox() 的 DestroyWindow 兜底修复
5) 所有仪表标题都显示 “Meter”
   → THRESHOLD::save() 写 wndcaption，但 load() 没读；已修复

6) 控件展示窗口的“双边框 / 浅色标题栏”（2026-10-27 修）
   → 对象显示窗口都是 WS_CHILD + WS_CAPTION + WS_THICKFRAME，系统按经典浅色
     画标题栏和 3D 边框；ob_threshold / ob_bandpower 又在客户区里画了一圈 2px
     浅色描边 → 看起来是双边框，而且在暗色主题上非常跳。
   修法（全程不碰客户区，避免重蹈 3) 的覆辙）：
     a. src\darkmode.cpp 新增 PaintDisplayFrame(hWnd, draw_caption)：
        只用 GetWindowDC()，把整块非客户区刷成暗色 RGB(22,22,26)，沿客户区画
        1px 描边 RGB(76,78,90)，标题文字用暗灰 RGB(156,158,170) 画在标题带里
     b. src\dialogs.cpp 的 CanvasClampSubclassProc 里拦 WM_NCPAINT/WM_NCACTIVATE
        调用它 —— 这个子类已经由 sweep_canvas_windows() 给主窗口的所有子窗口
        装上，所以一处改动覆盖全部对象显示窗口
     c. Meter_Class 的标题带留空（面板自己在客户区顶部画标题带，避免标题重复）
     d. 仪表窗口去掉 WS_CAPTION → 边框变成均匀 8px；Band-Power / Flash 保留
        WS_CAPTION（它们唯一的标题就写在标题带里）
     e. 删除 ob_threshold / ob_bandpower 在客户区内自绘的浅色 2px 外框
     f. 顺带修掉仪表下边缘把刻度“0”和阈值数字裁掉的问题：
        bottom=rect.bottom-10，右边缘阈值数字框加宽到 64px 并做上下夹紧
     g. 仪表顶端的大号数值被面板上沿裁掉：标题带高度原来按
        fontsize*2.4（像素）估，而数值字体是 fontsize*2（磅），实际行高更大
        → 数字顶部被切。现在用 GetTextMetrics() 量 st->font / st->valfont
        的真实行高再 +8px（上下各 4px 内边距），并夹在 METER_HEAD_H 与
        rect.bottom/2 之间（小面板不会被标题带吞掉）；标题/数值/单位统一
        DT_BOTTOM 对齐，数值右侧留 6px、单位再占 44px，都不贴边框
     h. 初始界面顶部那条被切一半的 “Welcome to BrainBay - Select demo session !”
        是自己造成的：SessionManager_Class 只有 WS_THICKFRAME（8px 边框、
        没有 WS_CAPTION），而画标题文字的条件只写了 “cr.top>6”，于是整句
        标题被塞进 8px 的窄带里上下都被切。现在必须先判断窗口样式：
        if ((GetWindowLong(GWL_STYLE) & WS_CAPTION) && (cr.top>=SM_CYCAPTION))
        才画标题文字 —— 没有标题栏的窗口（仪表、会话管理器）只画平面边框
   验证：截图确认三个仪表只剩自己的标题带、频带面板/Flash 标题为暗灰小字；
        bbay.log 仍是 “Flash: SetVariable() works”，画面正常推进
   教训：想改这些窗口的“边框”，只画非客户区（WM_NCPAINT）永远安全；
        在客户区里填充/描边就可能盖住 ActiveX 子窗口

7) 断开设备后：数值不清零、拼图继续跑（2026-10-28 修）
   → 原因：整条信号链只在“有样本”时才被驱动（TimerProc → process_physioamp →
      process_packets → objects[i]->work()）。设备一断就没有样本，各对象停在
      最后一帧；而 Flash 对象的 drive 模式自己用 GetTickCount 计时：
      In2（心跳）无条件每秒 +1、In1（计分）看闸门 last_value[gateport]（也停在旧值
      TRUE_VALUE=512）→ 于是拼图永远走下去。
   → 修法：给三个“展示类”对象各加一个“数据到达时间戳 + 超时看门狗”
      (ob_flash / ob_threshold / ob_bandpower 的 *.h 各加 DWORD last_data_tick)
      a. incoming_data() 里 last_data_tick = GetTickCount()
      b. 判定：只有 GLOBAL.running（会话在跑）且 last_data_tick != 0 且
         超过超时才认为“没数据”；超时 = Flash 1000 ms、仪表/频带面板 1500 ms
      c. Flash：flash_data_stale() 为真时 flash_gate_open() 返回 0，
         并且 flash_push_values() 冻结 clocktick/scoretick（In1/In2 不再变化）
         → In1In2InputModel 自动 pause，电影停住；日志写一次
         “Flash: no data for 1000 ms - puzzle paused (device disconnected?)”
         session_start() 里把 last_data_tick 置为当前时间，所以“根本没接设备就
         开始会话”也不会让拼图空转
      d. 仪表（Meter_Class）与频带面板（BandPanel_Class）：窗口里加 500 ms 的
         SetTimer 看门狗，超时就把 current_value/peak（仪表）或
         avgpow/rawpow（频带）清零并 InvalidateRect，WM_DESTROY 里 KillTimer
   → 注意：阈值/频带对象的“输出端口”值不会自己更新（没有样本就没有 work()），
     所以 Flash 闸门必须在 Flash 自己这边判超时，不能依赖上游清零

七、.con 文件规范（踩过的坑）
-------------------------------------------------------------------------------
* 属性名必须全小写（load_property 用 strstr 在转小写的缓冲里找）
* 颜色必须同时写 color / bkcol / fontcol / fontbkcol
  否则 loader 会强制白底
* 阈值：falsemode=0 不满足时输出 INVALID_VALUE(-32767)，满足时输出 1
* AND：两路都非 INVALID 时输出 TRUE_VALUE(512)
* 窗口几何 left/top/right/bottom 是相对主窗口的像素值
